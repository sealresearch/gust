# float32-t5-v1: operator modes for encoder-decoder T5 graphs

These modes serve T5-style encoder-decoder graphs. T5 needs four things `float32-graph-v1` and `float32-decoder-v1` lack: RMS
norm, ReLU, an additive relative-position bias on attention scores, and tied embeddings with one float16 scale per 64
weights. A fifth mode, grouped partial sums, makes one-row decoder steps fast. Every decoder build
(`GUST_FLOAT32_DECODER`) has these modes; there is no separate define.

- Capability bit 12 (4096); manifest `required_capabilities` entry `float32-t5-v1`, present exactly when a graph uses a
  mode below. the JavaScript binding reports `capabilities.float32T5` and refuses such a manifest on a build without the bit.
- Header, tensor, operator and context layouts do not change. Each mode uses an operator value or field that a
  runtime without it refuses (`GUST_SHAPE` or `GUST_FORMAT`) before it writes the arena.

| Operator             | Mode                                         | Meaning                                                                                                                           |
| -------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `F_NORM` (34)        | `p0 = 4`, `bias = 0`                         | RMS norm: `float32((x * (1 / sqrt(mean(x^2) + eps))) * gamma)` per row, evaluated in float64                                       |
| `F_UNARY` (35)       | `p0 = 3`                                     | ReLU: `x > 0 ? x : 0` (-0 and NaN give 0)                                                                                          |
| `F_MHA` (37)         | `p0 = 4`, `bias` = tensor index              | additive score bias, float32 `[heads * query rows, key rows]`: `score = float32(score + bias[(h * Q + i) * K + j])`; exact attention, never banded or fast |
| `F_MHA_PREFIX` (45)  | `kw = 1`, `bias` = tensor index              | additive score bias for this step, float32 `[heads, key rows]`: `score = float32(score + bias[h * K + j])`                          |
| `F_GATHER` (40)      | `kh = 1`                                     | float16 scales per 64 codes of a row (`mult` = float16 `[rows * ceil(C / 64)]`, the `F_CONV` group layout), so a tied embedding and its output projection share one blob |
| `F_CONV` (32)        | `p0 = 17` (16 with the group bit 1), `p1 = 4`, `kh = 1`, K a multiple of 64 | grouped partial sums: `y = bias; for each group g: p = 0; for k (increasing): p = p + float32(code) * x[k]; y = y + scale_g * p` |

The bias tensors are ordinary float32 tensors (normally inputs the host writes: relative position buckets are a host
concern, so the runtime stays generic). They are never state. `F_MHA` requires exactly the shape above (Q = rows of
the query tensor, K = rows of the key tensor); `F_MHA_PREFIX` requires `[heads, rows of the key tensor]`. With
`gust_run_valid`, only rows below the valid counts are read. Scores are computed as before
(`float32(dot64 * scale)`); the bias is one float32 addition before the maximum, and the rest of the softmax and the
value sum are unchanged.

Grouped partial sums are the factored order of the dedicated T5 runtime such graphs are trained against: the integer codes
multiply the inputs and each group is scaled once. Every code is read once per row instead of restoring
`code * scale` panels first, about 2.5x faster for one-row decoder steps. One-row and several-row executions perform
the same operations in the same order, so the row count never changes a bit.

Numerics: no fused operations and no host libm (the RMS norm's square root is `__builtin_sqrt` on a float64, as in
LayerNorm). Native and WebAssembly builds, SIMD or not, produce identical bits. Tests: `runtime/tests/t5.c` (every
mode against its contract, refusals).
