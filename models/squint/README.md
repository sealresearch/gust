# Squint

Squint reads QR codes from a live camera when the camera, or the hand holding the code, will not keep still. Most readers
look at one frame at a time, and a frame smeared by motion blur is lost. Squint remembers where the code was, follows it
into the next frame, and reads it again from what that frame shows. It only returns a payload that the current frame
supports.

It is a **research model**: measured on one webcam, with the limits listed in [MODEL_CARD.md](MODEL_CARD.md).

| Property | Value |
|---|---|
| Weights | none: every part is a hand-built algorithm in C |
| Size | about 0.5 MB of compiled code per target |
| Runs on | x86-64, ARM64 and WebAssembly, on the Gust runtime, with no GPU and no server |
| Memory | 45 MB of fixed memory (measured), none allocated while reading |
| Licence | MIT |
| Write-up | [seal.computer/research/squint-1](https://seal.computer/research/squint-1) |

## Use it

Squint is a model of the Gust model API like any other. Frames go in as gray (or RGBA) images, in order, and each read comes
back as JSON:

```c
#include "gust_model.h"

gust_model *m;
gust_model_open("squint-1", NULL, 0, NULL, &m);

gust_buffer frame = {sizeof frame, GUST_BUF_IMAGE_GRAY8, gray, 1280 * 720, 0, 0, 1280, 720};
gust_result *out;
gust_model_run(m, &frame, 1, "{\"time\": 1033.3}", &out);          // time: the frame's time in milliseconds
puts(gust_result_get(out, 0)->data);
// {"accepted":true,"reason":null,"path":"Current-image hinted native QR decoder","version":2,
//  "payload":"48656c6c6f","text":"Hello","corners":[[x,y],[x,y],[x,y],[x,y]]}
```

`payload` is the code's bytes in hex, `text` the same as UTF-8 when it is valid (otherwise `null`), `corners` the four
corners clockwise from the top left. Payload bytes are untrusted input: a QR code can carry any text, including a link
you do not want to open. When nothing is read, `accepted` is false and `reason` says why.

For a camera, open a stream (`gust_stream_open`), push every frame and pull each read; the stream forgets earlier codes
when it opens. Run options: `time`, `reset`, `budget_ms` (and `acquire_budget_ms`, `tracked_acquire_budget_ms`) and
`acquire_every`. Without budgets a read depends on the frames alone, which is how the tests run.

One reader can be open at a time, because the hosts keep their state in static memory. Frames are at most 1280 x 720.
From Python and JavaScript the model loads like the others (`Model.load("squint-1")`).

## What is here

```
host/    the C host: the pipeline (squint.c) on top of the hosts for geometry, decoding, white patches, optical flow,
         registration, the evidence certificate and acquisition; generated headers for the symbol prefixes (see below)
sdk/     the Gust model plugin (squint_model.c)
tests/   regressions: the reader against recorded reference outputs, bit for bit
tools/   generators for the headers, the test sequences and the comparison with the JavaScript release
```

The hosts keep their state in static variables, and Squint needs several independent copies of some (the tracker's and the
acquirer's verifier, the standalone geometry and decoder). Each copy is compiled with its own symbol prefix, listed in
`host/names_<instance>.h` and generated by `tools/gen_names.py`; `tools/build_hosts.sh` builds them for a target and
`build.sh` links them into the library.

## Build and test

```sh
ZIG=/path/to/zig ./build.sh lib wasm-models          # libgust with Squint built in, and the WebAssembly model module
bash models/squint/tools/build_hosts.sh x86_64-windows-gnu   # just the objects
```

The C port returns the same reads as the JavaScript release for the same frames, down to the last bit of every corner.
`tools/compare.mjs` checks that on the sequences from `tools/make_sequences.mjs`.
